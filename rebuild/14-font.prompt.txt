Your type block is on the page and none of it is winning. Two causes, both
measured in the browser.

# 1. The face is not loaded

    the page requests   Archivo:wght@600;800
    your rule asks for  Instrument Serif
    what renders        Georgia

`Instrument Serif` is named in your CSS and never fetched, so every rule that
asks for it falls through to the next name in the stack. The original loads it
from Google Fonts alongside Archivo and IBM Plex Mono:

    https://fonts.googleapis.com/css2?family=Archivo:wght@400;500;600;700
      &family=IBM+Plex+Mono:ital,wght@0,400;0,500;1,400
      &family=Instrument+Serif:ital@0;1&display=swap

The page already has a stylesheet link. Add what is missing to it, or add a
second link. Nothing renders in the right face until the face is there.

# 2. Your two blocks are fighting each other

    winning rule   .rv-sentence { Georgia, "Iowan Old Style", "Times New Roman", serif }
    losing rule    .stand { Instrument Serif, ... }

The block you wrote for the instrument's setting gives the sentence the class
`rv-sentence` and sets Georgia on it. The block you wrote for the type sets
Instrument Serif on `.stand`. Same element, and the first one wins.

Decide once, in one block, and make the type rules address every class the
element actually carries: the sentence is
`<p class="stand rv-sentence" data-rv="1">`.

Two of these are worth saying why.

The count is monospace inside a serif sentence, and rust. A figure set in another
face says this is a measurement rather than a word, and rust is this design's
colour for a chosen selection. Set in the same serif as the sentence it reads as
prose.

The aim line is currently rgb(93,74,114), a purple. Nothing on this page is
purple. It is where the instrument says what you are pointing at, so it is rust.
