## Three faults a reader can see

**Hovering anything shoves the page down.** Hover a zone row, the drawing, or a
month bar and everything below the pointer jumps. The parent does not do this at
all.

    parent   112 controls hovered   0 layout shifts
    /z       115 controls hovered   46 shift the layout, worst single move 485px

`build/verify_presentation.py` reports that figure and is the gate for this brief.

One element causes all of it. `<div class="aim" id="aimLine" aria-live="polite">`
is empty at rest and has no height. On hover it fills with the aim text and grows,
and every element after it in flow moves:

      div.hand     y 121.9 -> 128.4     "Click a zone on the aircraft..."

      div.sdcount  y 144.1 -> 150.6     the headline
      div.rails    y 183.1 -> 189.6
      page height  2129.8 -> 2136.3

**Two figures are cut off mid-number.** The gutter values are ellipsised because
their boxes are narrower than their text:

    span.gv   72px box / 95px  text    "54,634 aircraft"       -> 54,634 air...
    span.gv   50px box / 126px text    "151,543 of 1,757,827"  -> 151,54...
    parent, same width: 0 ellipsised elements, both printed in full

A count truncated mid-digit is the one failure this page cannot afford. It is the
page's own argument that the FAA's numbers should be readable.

**Label text is printed underneath a button.** In the group strip, the figure in

390px the same strips run off the screen: twenty elements outside the viewport,
the document scrolling sideways to 698px. At 768px and above there is no overflow
at all, so this is the narrow case only.

# What to build instead

Own your names. A block that introduces a class must not reuse a name another
block already means something else by. Where a name is genuinely shared, it must
be shared deliberately, from the tokens in `:root`, and mean the same thing in
both places. `rebuild/splice_css.py` will now fail the build on any selector where
two blocks set one property to two values, so this cannot come back silently.

Take the type scale from the tokens rather than restating it. A label and the
number beside it are one row and read as one row; they take one size. Where the
parent sets 12px for both, the clone has no reason to set 15 and 11.

A live region that appears on hover must not be able to move the page. Reserve its
height. A reader aiming at a zone is pointing at a target that moves out from
under the pointer, and no amount of correct content in that region is worth that.

A number is never truncated. If the gutter cannot hold "151,543 of 1,757,827",
the gutter is the wrong width, or the value wraps, or it is written shorter on
purpose - but the digits that are printed are all the digits there are.

A label and the buttons beside it are two columns, not two things drawn in the
same place. At narrow widths the buttons wrap or their strip scrolls on its own;
the page body never scrolls sideways.

Declare a focus ring once. `outline: none` on a focusable control is not a style
choice available here, and the month bars are how the WHEN rail is operated. Six
declarations of one selector, where the ring survives on source order alone, is
the same fault as the rest of this brief and it is one edit away from a page you
cannot operate by keyboard.
